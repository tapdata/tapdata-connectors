# Streaming SQL command parameters

All SQL connectors using `CommonDbConnector` or `SqlExecuteCommandFunction` share these parameters. The `execute` / `executeQuery` command accepts `params.sql` (SQL text), `params.batchSize` (whole number, default 1000; zero and negative int values retain the default batch size) and `params.queryTimeoutSeconds` (whole seconds from 0 through 2147483647). An absent or zero timeout leaves the JDBC statement timeout unset; negative, fractional, nonnumeric and overflowing values fail validation. Positive values call `Statement.setQueryTimeout` before executing SQL. Cancellation and timeout enforcement depend on the JDBC driver.

A driver that rejects timeout configuration returns an explicit `SQLFeatureNotSupportedException`; the command does not silently continue without the requested timeout. Omit the parameter or explicitly set it to 0 to run without that guarantee. Legacy `SqlExecutor` implementations and `CommonDbConnector` subclasses that override only the original `execute` method preserve their original path with zero/absent timeout; requesting a positive timeout requires implementing the new overload, otherwise it returns an explicit unsupported-operation error. Streaming commands can have delivered earlier batches before a JDBC error occurs.

The engine custom query inspection owns the 1000-result-row limit. It counts across callbacks and throws on row 1001; JDBC resources close when the consumer throws. No new connector API or row-limit parameter is required. Results delivered before an error must be discarded by inspection, never compared as a complete result.
